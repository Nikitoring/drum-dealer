# Архитектурные решения

Документ фиксирует решения, которые влияют на развитие проекта. Записи должны отражать принятое решение, контекст и последствия.

## ADR-001. Monorepo с отдельными frontend и backend

**Решение:** frontend и backend живут в `apps/frontend` и `apps/backend` и управляются npm workspaces.

**Причина:** отдельный цикл сборки и ответственности при общем репозитории, документации и локальном запуске.

## ADR-002. PostgreSQL и Prisma как источник истины

**Решение:** доменная модель хранится в Prisma schema, изменения базы проходят через миграции.

**Причина:** типизированный доступ из NestJS, явная история изменений и транзакции для заявок и слотов.

## ADR-003. Заявка резервирует слот атомарно

**Решение:** при создании заявки слот переводится из `AVAILABLE` в `PENDING` условным обновлением внутри транзакции.

**Причина:** два параллельных запроса не должны создать две активные заявки на один слот.

## ADR-004. Изображения хранятся отдельно от базы

**Решение:** бинарные файлы загружаются в S3-compatible storage, а в PostgreSQL сохраняются URL, тип и позиция.

**Причина:** база хранит только метаданные и связи, а файловое хранилище отвечает за объекты.
